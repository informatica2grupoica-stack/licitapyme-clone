# Forma de trabajo con el dueño del proyecto

Reglas que valen para todos los módulos. Traspasado desde la memoria personal el 2026-10-27.

- **Responder siempre en español, con registro chileno natural** (cercano, no informe
  corporativo), sin sacrificar la claridad técnica.
- **Datos reales, nunca inventados ni aproximados.** Si el dato real existe en la BD, se usa.
  Caso que lo fijó (2026-07-31): 34 entregas decían «Ganado el 30 de julio», la fecha del script de
  carga, no la de cada adjudicación.
- **Arreglos generales, nunca un parche para una licitación** («todas las licitaciones son
  distintas»). El caso real sirve para encontrar el patrón; verificar con la suite completa.
- **El dueño hace commit, push y deploy él mismo.** No ofrecer hacerlo salvo que lo pida.
- Todo tiene que entenderse «hasta por un niño»: textos simples en pantalla, sin jerga.
- Probar sin molestar a los asistentes: no generar avisos, aprobaciones ni datos visibles para
  ellos; marcar los datos de prueba («PRUEBA QA») y restaurar lo que se toque.
- Decisiones del negocio (aprobar, firmar, confirmar) las toma el equipo con su nombre, nunca la
  IA.
- Decir con claridad qué se verificó y qué no (navegador, IA real, producción).
